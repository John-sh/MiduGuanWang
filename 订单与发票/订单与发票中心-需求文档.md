# 订单与发票中心 · 需求文档

> 适用对象：产品讲解、评审、前端/后端落地  
> 当前形态：官网控制台 **PC 静态原型**（无后端接口，数据写在前端）  
> 文档对照版本：本地工作目录 `orders/`，静态资源 `?v=20260910a`  
> 更新日期：2026-09-10

---

## 1. 背景与目标

蜜度官网控制台需要一个独立的 **订单与发票中心**，让客户在同一处完成：

1. 确认绑定主体  
2. 查看、支付、取消订单  
3. 对已完成订单申请电子发票，并查看开票记录  

本原型用于确认信息架构、字段规则和主流程，后续可对接真实订单、抬头库与开票服务。

### 1.1 本期范围

| 纳入 | 不纳入 |
| --- | --- |
| 绑定主体填写与确认 | 真实支付网关、税控开票接口 |
| 订单列表 / 详情 / 支付 / 取消 | 账号登录、权限、多抬头管理 |
| 单笔与多选合并开票 | 纸质发票、发票下载文件流 |
| 开票记录查询与失败重申 | 移动端适配、打印、导出 Excel |

### 1.2 成功标准（产品）

- 讲解时能沿「确认主体 → 支付订单 → 开发票 → 看记录」走完一遍。  
- 讲解时能演示：多选合并开票、专用/普通票、企业/非企业、客服扫码、失败重申。  
- 规则口播与界面行为一致，不出现「点了专用票却被改成普通票」这类跳转。

## 2. 信息架构

页面标题：**订单与发票中心**  
默认进入：**订单管理**

```
顶栏（蜜度 Logo / 帮助 / 产品导航 / 账号）
└─ 左侧导航
   ├─ 绑定主体     状态：未确认 / 已确认
   ├─ 订单管理     角标：订单总数
   └─ 发票管理     角标：开票记录条数
```

侧栏提示文案：请先确认绑定主体。待支付可继续付款；已完成订单可申请电子发票。

## 3. 绑定主体

### 3.1 目标

客户先落下一套抬头信息。确认后，后续开票表单只读引用该主体，不再现场手填税号和邮箱。

### 3.2 字段

发票类型、抬头类型可任意组合，**互不强制改写**。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 发票类型 | 是 | 专用电子发票 / 普通电子发票（默认普通） |
| 抬头类型 | 是 | 企业单位（默认）/ 非企业单位 |
| 公司名称 / 发票抬头 | 是 | 企业单位显示「公司名称」；非企业单位显示「发票抬头」。必须从匹配列表中选中一条 |
| 公司税号 / 单位税号 | 普通选填 / 专用必填 | 企业单位显示「公司税号」；非企业单位显示「单位税号」。填了则须为 15–20 位大写字母或数字；选中名称后自动带出 |
| 开户银行 | 普通选填 / 专用必填 | 专用票时标签带 `*` |
| 银行账号 | 普通选填 / 专用必填 | 同上 |
| 注册地址 | 普通选填 / 专用必填 | 同上 |
| 注册电话 | 普通选填 / 专用必填 | 同上 |
| 电子邮箱 | 是 | 电子发票接收邮箱 |
| 备注 | 否 | 将体现在发票上，最多 80 字 |

企业单位与非企业单位共用同一套表单和匹配校验，**文案随抬头类型切换**。专用票额外要求银行四项与税号必填；普通票税号与银行四项均为选填。

### 3.3 公司名称匹配（演示规则）

输入即过滤。下拉展示匹配项；底部固定：无匹配单位名称，请 **联系客服** 获取发票。

当前演示库：

| 公司名称 | 税号 |
| --- | --- |
| 上海示例科技有限公司 | 91310000MA1SH0012X |
| 北京示例信息技术有限公司 | 91110000MA1BJ0013Y |
| 深圳示例网络有限公司 | 91440300MA1SZ0014Z |

行为：

- 选中名称 → 自动填税号。  
- 改名后不再精确匹配 → 清空税号。  
- 未精确匹配就点确认 → Toast「无匹配单位名称，请联系客服获取发票」，并展开下拉。  
- 「联系客服」打开企微弹窗（二维码 + 热线 400-600-7505 + 工作日 9:00–18:00）。

### 3.4 确认与再编辑

- 未确认：导航和标题旁显示「未确认」，按钮文案「确认主体」。  
- 已确认：显示「已确认」。  
- 确认后若再改表单，状态回到未确认，需重新确认后才能开票。

### 3.5 校验失败提示

| 条件 | Toast |
| --- | --- |
| 未填名称 | 企业：请填写公司名称；非企业：请填写发票抬头 |
| 名称不在列表 | 无匹配单位名称，请联系客服获取发票 |
| 专用票未填税号，或税号格式非法 | 企业：请填写正确的公司税号；非企业：请填写正确的单位税号 |
| 普通票填了税号但格式非法 | 同上 |
| 专用票缺银行四项 | 请填写开户银行 / 银行账号 / 注册地址 / 注册电话 |
| 邮箱格式错误 | 请输入正确的电子邮箱 |

## 4. 订单管理

### 4.1 列表

列：勾选、订单编号、产品、订单金额、订单状态、操作。  
筛选：全部 / 待支付 / 已完成 / 已取消。  
分页：每页 10 条，页码 + 跳至 N 页。

### 4.2 订单状态与操作

| 订单状态 | 开票阶段 | 操作 |
| --- | --- | --- |
| 待支付 | — | 取消订单、去支付 |
| 已取消 | — | 订单详情 |
| 已完成 | 未开票 | 订单详情、开发票；可勾选 |
| 已完成 | 开票中 | 订单详情、开票中（禁用） |
| 已完成 | 已开票 | 订单详情、查看发票 |
| 已完成 | 开票失败 | 订单详情（列表不直接给开发票，从发票记录「重新申请」） |

可勾选条件（同时满足）：已完成、`canInvoice`、未开票、当前无进行中/已开票记录。

### 4.3 多选统一开票

- 仅可开票行可勾选；待支付、已取消、开票中、已开票勾选框为灰态。  
- 表头勾选：全选 **本页** 可开票订单。  
- 勾选可跨页保留。  
- 底部显示已选笔数、合计金额；有选中才可点 **统一开票**。  
- 行内「开发票」只开当前这一笔（覆盖当前勾选为该单）。

### 4.4 订单详情（右侧抽屉）

展示：状态、金额、产品、订单编号、价格、数量、订单金额、订单状态、支付方式（若已支付）、下单时间。不展示产品版本。  
权益详情：产品权益条目列表。  
底部操作与列表一致（不含「订单详情」按钮）。

点击行空白区域也可打开详情；点击勾选框不打开详情。

### 4.5 支付

待支付订单点「去支付」打开弹窗：

- 展示订单编号、产品、应付金额  
- 支付方式：支付宝（默认）、微信支付  
- 确认支付后：状态变为已完成、可开票，记录支付方式  
- Toast：`支付宝支付成功，可申请开票` 或微信支付对应文案  

取消订单：仅待支付可取消，取消后不可开票。

## 5. 发票管理

只保留 **开票记录**，不再提供「可开发票」独立栏目。申请入口在订单管理。

### 5.1 记录列表

筛选：全部 / 开票中 / 已开票 / 开票失败。

列：发票信息、申请时间、订单金额、状态、操作。

发票信息主标题为关联产品名；副标题为发票编号 + 公司名（多笔显示「共 N 笔订单」）。  
点击行打开发票详情。

| 状态 | 操作 |
| --- | --- |
| 开票中 | 无列表按钮 |
| 已开票 | 重新发送 |
| 开票失败 | 重新申请 |

### 5.2 申请开票流程

```mermaid
flowchart LR
  A[订单管理勾选或点开发票] --> B[填写开票信息]
  B --> C{主体已确认?}
  C -->|否| D[提示去绑定主体]
  C -->|是| E[选择抬头并核对]
  E --> F[确认开票信息]
  F --> G[写入开票记录 状态开票中]
  G --> H[跳转发票管理]
```

填写开票信息弹窗：

- 未确认主体：黄条提示 + 「去绑定主体」  
- 已确认：下拉选择该抬头（必选）  
- 只读：税号（有值才显示，文案随企业/非企业为「公司税号」或「单位税号」）、邮箱、发票类型、抬头类型、银行四项（有值才显示）、发票格式 PDF、发票内容 `*信息技术服务*平台服务费`、开票订单摘要、发票金额  
- 备注可改，默认带主体备注  

提交后二次确认，确认提交：

- 新增记录，状态「开票中」，邮件状态「待发送」  
- 相关订单标记已开票，不可再勾  
- 跳转发票管理 · 全部  
- Toast：开票申请已提交，完成后将发送至邮箱

### 5.3 发票详情

展示状态、金额、发票编号、发票类型、公司名称或发票抬头、税号（有值才显示，文案为公司税号或单位税号）、发票内容、备注（若有）、格式 PDF、申请时间、电子邮箱、发送状态。

底部：已开票可重新发送；失败可重新申请；开票中可关闭。

### 5.4 重新发送 / 重新申请

- 重新发送：发送状态改为「已发送」，Toast「电子发票已重新发送至邮箱」。  
- 重新申请：该失败记录与订单解绑，订单重新变为可开票，并打开开票表单（勾选原订单）。失败记录仍留在列表中（`orderIds` 清空）。

## 6. 关键业务规则（实现对照）

1. **先主体后开票**：未确认或未选择抬头，不能提交开票。  
2. **仅已完成未开票可开**：待支付、已取消不可开。  
3. **一单同时只对应一张有效开票进度**：开票中 / 已开票后不可再开。  
4. **可合并开票**：多笔已完成未开票订单可合成一张，金额为合计。  
5. **发票类型与抬头类型独立**：专用 + 非企业、普通 + 企业等均可选择，不再自动改写另一项。  
6. **专用票银行四项与税号必填**；普通票税号与银行四项均为选填。  
7. **名称必须命中抬头库**（原型为本地三家示例公司）。非企业单位名称字段文案为「发票抬头」，税号文案为「单位税号」。  
8. **发票内容固定**：`*信息技术服务*平台服务费`。  
9. **格式固定**：PDF 电子发票，发送至主体邮箱。

### 8.3 前端数据结构（落地时可映射接口）

**订单 Order**

| 字段 | 含义 |
| --- | --- |
| id | 订单编号 |
| product / benefit[] | 产品、权益（无产品版本字段） |
| price / qty / amount | 单价、数量、订单金额 |
| date | 下单时间 |
| status | pending_pay / completed / cancelled |
| canInvoice / invoiced / invoiceId | 是否可开、是否已开、关联发票 |
| payMethod | 支付宝 / 微信支付 |

**开票记录 Record**

| 字段 | 含义 |
| --- | --- |
| id / invoiceNo | 申请号 / 发票号码 |
| status | processing / issued / failed |
| amount / count / orderIds[] | 金额、笔数、订单 |
| company / tax / type / invoiceKind / remark | 抬头、税号、抬头类型、票种 |
| email / emailStatus | 接收邮箱与发送状态 |

**绑定主体 Entity**：confirmed、invoiceKind、type、company、tax、bank、account、address、phone、email、remark。

### 8.4 建议接口（正式开发）

| 能力 | 建议 |
| --- | --- |
| 绑定主体 | 查询 / 保存确认；抬头模糊搜索走主数据，禁止前端写死三家公司 |
| 订单 | 分页列表、详情、取消、创建支付单、支付回调后可开票 |
| 开票 | 创建申请（支持 orderIds[]）、查询记录、重发邮件、失败重申 |
| 客服 | 企微二维码与热线配置化，不要写死在页面 |

分页、金额精度、税号校验、邮箱校验应在服务端再做一遍。普通票税号选填、专用票税号与银行四项必填，以税务与财务规则为准，与原型保持一致即可。

## 9. 界面与体验约定

- 控制台风格：顶栏深色 `#1b2434`，主色蓝 `#2b7cff`。  
- 状态色：已完成/已开票绿、待支付橙、开票中蓝、失败红、取消灰。  
- 金额右对齐；订单表勾选列固定宽度，避免表头与行错位。  
- 反馈以 Toast 为主，时长约 1.8 秒。  
- 抽屉、支付、开票、确认、企微为遮罩弹层；关遮罩关闭对应层。
