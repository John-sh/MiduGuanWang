# 蜜度 BOSS · 线上订单 & 线上订单发票 需求文档

> 版本：V1.1  
> 日期：2026-09-08  
> 适用对象：产品讲解、交互确认、前后端开发  
> 原型入口：
> - 线上订单：`?page=order`（菜单：订单管理 / 线上订单）
> - 线上订单发票：`?page=invoice`（菜单：收支管理 / 线上订单发票）

## 1. 背景与目标

官网（含小程序）支付成功的订单进入 BOSS，运营人员在后台完成两类工作：

1. **查订单**：核对购买内容、支付、服务周期、开票进度、到账、权益用量。
2. **管发票**：按官网支付订单开具、跟踪、归档电子发票，并留存附件。

本需求覆盖两个独立菜单页面，数据同源（官网支付订单），职责不同：

| 模块 | 菜单位置 | 主职责 | 列表操作 |
| --- | --- | --- | --- |
| 线上订单 | 订单管理 / 线上订单 | 看订单全貌 | 仅「详情」 |
| 线上订单发票 | 收支管理 / 线上订单发票 | 看开票与到账 | 仅「详情」 |

**产品原则**

- 订单来源于官网支付，BOSS 运营不在列表上直接开票、退单、作废重开。
- 「下单需谨慎，所有订单需计收开票」：有支付即应进入开票管理视野。
- 发票数据来源于官网支付订单，列表提示：`*线上订单发票来源于官网支付订单。`

## 2. 业务关系

```
官网 / 小程序下单
        │
        ▼
   支付成功（微信 / 支付宝）
        │
        ├──────────────► 线上订单（一单一条）
        │                     │
        │                     ├ 订单明细
        │                     ├ 开票信息（可 0～N 条）
        │                     ├ 到账流水
        │                     ├ 累计权益总量
        │                     └ 操作记录
        │
        └──────────────► 线上订单发票（一张发票一条；可对应 1～N 笔订单）
                              │
                              ├ 订单信息（表格，一行一单）
                              ├ 发票信息（开票 / 收件 / 到账流水）
                              ├ 附件信息
                              └ 操作记录
```

关联键：

- 订单侧：`订单编号`（官网统一订单号）
- 发票侧：`发票号`（未开具可空）；详情通过 `orders[]` 挂多笔订单

**一张发票可以对应多笔订单**（同一抬头合并开票）。订单详情「开票信息」Tab 回显该订单关联的发票；用户名、账号、付款编号只在发票详情「订单信息」表中按行展示，不出现在发票列表。

## 3. 公共字典

### 3.1 订单状态

仅两种，**没有「退单」状态**。客户退款、重复购买等场景，订单状态记为「作废」。

| 值 | 含义 | 列表样式 |
| --- | --- | --- |
| 正常 | 有效订单 | 绿色标签 |
| 作废 | 已失效（含退款、作废重下等） | 灰色标签 |

### 3.2 开票状态

| 值 | 含义 | 列表样式 |
| --- | --- | --- |
| 待开票 | 已提交或应开，尚未进入开具 | 蓝色 |
| 开票中 | 已进入开具流程，尚未出票 | 橙色 |
| 已开票 | 已开具，通常已有发票号 | 绿色 |
| 已作废 | 发票作废（随退单/作废等） | 灰色；发票列表行弱化 |

状态流转（产品口径）：

```
（支付成功，用户提交开票）
        │
        ▼
     待开票 ──► 开票中 ──► 已开票
        │          │
        └──────────┴──► 已作废
```

- 未提交开票的订单：线上订单详情「开票信息」可为空。
- 已开票后作废：开票状态变为「已作废」，发票号可保留用于追溯。
- **列表不提供「作废重开」按钮。**

### 3.3 单位属性

| 值 | 开票信息要求（产品口径） |
| --- | --- |
| 企业单位 | 需税号、注册地址/电话、开户行、银行账号等企业开票字段 |
| 非企业单位 | 抬头可为个人姓名；税号、地址、电话、开户行、账号可空 |

### 3.4 支付方式

`微信`、`支付宝`。

### 3.5 发票类型 / 开票类型

`专票电子票`、`普票电子票`。

发票列表筛选项与列表列使用「发票类型」；开票详情「开票信息」字段名为「开票类型」，取值相同。

### 3.6 产品（当前原型样本）

| 产品 | 出现模块 | 说明 |
| --- | --- | --- |
| 蜜度GEO | 线上订单 | 小程序评估套餐，单价 9.90 |
| 舆情平台 / 蜜度DataQ / 海外传播 / 智库报告 | 线上订单发票 | 官网套餐样例 |

生产环境产品字典由官网商品中心提供，BOSS 只读展示。

### 3.7 附件类型（仅发票模块）

`电子发票`、`开票资料`、`资质文件`、`开票申请`、`其他`。

## 5. 模块二：线上订单发票

### 5.1 页面定位

财务/运营处理官网支付订单的开票：查进度、导出开票信息、查看税号账户、上传电子发票附件。  
列表操作列 **仅「详情」**，**不提供「作废重开」**。

### 5.2 筛选区

| 筛选项 | 控件 | 匹配规则 |
| --- | --- | --- |
| 产品 | 下拉 | 精确 |
| 发票号 | 文本 | 包含；未开票可为空 |
| 开票状态 | 下拉：已开票 / 待开票 / 开票中 / 已作废 | 精确 |
| 公司 | 下拉（开票主体） | 精确；样例：蜜度科技股份有限公司 |
| 发票类型 | 下拉：专票电子票 / 普票电子票 | 精确 |
| 支付方式 | 下拉：微信 / 支付宝 | 精确 |
| 单位属性 | 下拉：企业单位 / 非企业单位 | 精确 |
| 发票抬头 | 文本 | 包含 |
| 开票提交时间 | 日期范围 | 按提交日期 |
| 开票日期 | 日期范围 | 按实际开票时间 `invoiceTime` |

按钮：查询、重置、导出。

**发票列表不提供用户名、账号、付款编号筛选。** 这些字段只在详情「订单信息」表格中按订单行展示。

### 5.3 统计面板（随当前筛选结果计算）

| 指标 | 计算 |
| --- | --- |
| 待开票金额 | 开票状态=待开票 的 `开票金额` 合计 |
| 开票中金额 | 开票状态=开票中 的 `开票金额` 合计 |
| 已开票金额 | 开票状态=已开票 的 `开票金额` 合计 |
| 已作废金额 | 开票状态=已作废 的 `开票金额` 合计 |
| 到账金额 | 当前结果集 `到账金额` 合计（含各状态） |
| 发票总数 | 当前筛选条数 |

金额展示：千分位，两位小数。

### 5.4 工具栏

- 导出开票信息（勾选行或当前筛选，生产实现时需确认范围）
- 分页：每页 10 条

提示文案：`*线上订单发票来源于官网支付订单。`

### 5.5 列表列

勾选、#、产品、发票号、开票状态、公司、支付方式、支付时间、开票提交时间、单位属性、发票抬头、纳税人识别号、注册地址、注册电话、开户银行、银行账号、发票内容、开票日期、开票金额、发票类型、到账金额、到账日期、未到账金额、操作（详情）。


## 6. 金额与时间口径

| 名称 | 口径 |
| --- | --- |
| 单价 / 价格（总价） | 人民币，两位小数，千分位展示 |
| 订单总价 | 明细小计之和；GEO 样例 = 单价 × 数量 |
| 开票金额 | 本次申请开具金额，通常等于订单总价 |
| 到账金额（列表） | 已入账合计（退款为负时按流水汇总） |
| 未到账金额 | `max(开票金额 − 到账金额, 0)` |
| 下单时间 / 支付时间 / 开票提交时间 / 开票时间 | `YYYY-MM-DD HH:mm:ss` |
| 服务开始/终止、开票日期筛选 | 日期，按字段日期部分比较 |
| 服务天数 | `round((终止日 − 开始日) / 1 天)` |

金额字段空值界面显示空字符串，不当成 0 展示（计算时按 0）。

## 8. 产品讲解要点

讲解时可按「先订单后发票」走一遍同一笔 GEO 样例：

1. **线上订单列表**：看套餐描述、支付方式、单位属性、订单状态；强调没有发票号列，运营点「详情」。
2. **订单详情**：用户名/账号/付款编号只在这里出现；开票信息 Tab 看进度和税号，没有发票号。
3. **切到线上订单发票**：同一支付订单进入开票作业；列表很宽，税号账户全在表上方便财务导出。
4. **强调列表没有用户名/账号/付款编号**，避免财务宽表泄露支付侧账号。
5. **开票详情**：先看「订单信息」表，一票多单时有多行；再看「发票信息」讲票面、发票号、公司、金额；附件里上传电子发票 PDF。
6. **状态**：订单只有正常/作废；发票四态。已作废行变灰，统计里单独有「已作废金额」。

### 8.1 样例数据（便于演示）

| 场景 | 订单编号（发票模块样例） | 开票状态 | 说明 |
| --- | --- | --- | --- |
| 已开普票（一票两单） | 25312000000123456789 | 已开票 | 订单 OL202608280017 + OL202608280042 合并开票，金额 13,780.00 |
| 待开专票 | OL202609010008 | 待开票 | 发票号空 |
| 开票中 | （见原型） | 开票中 | 已提交未出票 |
| 已作废 | （见原型） | 已作废 | 行弱化 |

GEO 订单样例：`GEO202608050019`（正常、尚未开票）、`GEO202608040083`（开票中）、`GEO202608030057`（已开票，非企业单位个人抬头）、`GEO202607280061`（订单作废，发票已作废）。

### 8.2 文案对齐说明

- 订单模块统一用 **套餐描述**。
- 发票详情「订单信息」表列名为 **套餐权益**，语义同订单模块「套餐描述」。实现时建议统一字段名，或订单存 `packageDesc`、发票详情只读展示该字段。

## 10. 待确认（不影响按原型开发）

1. 一笔订单是否允许拆分到多张发票（部分开票）。一张发票对应多笔订单已确认。
2. 「导出」与「导出开票信息」差异：全量筛选 vs 勾选行。
3. 列表注册地址/电话 与 详情开票地址/电话 是否强制同一套购方信息。
4. 非企业单位开专票时税号是否必填（税务合规，需财务确认）。
5. 附件「签收时间」由谁写入（客户确认收到 / 运营标记）。
6. 订单作废后，对应发票是否必须同步「已作废」，以及已开票是否走红冲。
