# 蜜度 BOSS · 联系人管理 / 联系人列表 需求文档

> 版本：V1.1  
> 日期：2026-09-10  
> 适用对象：产品讲解、交互确认、前后端开发  
> 所属模块：联系人管理 / 联系人列表  
> 字段来源：《联系人表单0910》  
> 原型入口：菜单「联系人管理」 / `?page=contact` / `contact.html`
>
> **结构约定**：主表字段出现在联系人**列表**；子表（完整轨迹）出现在**详情**。

---

## 1. 背景与目标

运营在 BOSS 中查看官网/小程序注册的联系人主档，并点进详情查看该联系人按产线记录的行为轨迹与意向温度（冷/温/热）。

当前样例产线：**蜜度GEO小程序评估套餐**。行为分按产线分开计算。

| 模块 | 菜单位置 | 展示内容 | 操作 |
| --- | --- | --- | --- |
| 联系人列表 | 联系人管理 | 主表字段 | 仅「详情」 |
| 详情弹窗 | 列表点详情 | 子表：行为汇总 + 行为轨迹 | 关闭 |

联系人 ≠ 客户。客户管理菜单保留。

---

## 2. 主表 → 列表字段

列表列（另加序号、操作）即主表全部业务字段：

| 字段名 | 中文名 | 必填 | 说明 |
| --- | --- | --- | --- |
| contact_id | 联系人ID | 是 | 主键 |
| official_account_id | 官网账号ID | 是 | 官网注册账号 |
| mobile | 手机号 | 是 | 仅登录用户可为空；敏感字段 |
| customer_subject_id | 客户主体ID | 否 | 关联 CRM 客户/企业主体 |
| customer_subject_name | 客户主体名称 | 否 | 冗余展示 |
| email | 邮箱 | 否 | 绑定主体后才有 |
| name | 联系人姓名 | 否 | 绑定主体后才有 |
| openid | 小程序openid | 否 | 小程序用户唯一标识 |
| unionid | 微信unionid | 否 | 跨应用统一身份 |
| source | 来源渠道 | 是 | 小程序、官网… |
| source_detail | 来源详情 | 否 | 如 GEO小程序 |
| primary_product_line_id | 意向产品线 | 否 | 触达过的产品线，如 `[1,3]`，列表展示名称 |
| purchased_product_lines | 已购产品线 | 否 | 已购买的产品线；买过 GEO 则存「蜜度GEO小程序评估套餐」 |
| identity_status | 身份状态 | 是 | 已注册未下单 / 已下单未开票 / 已绑定主体 / 已开票 |
| behavior_score | 行为分 | 否 | 默认 0，按产线动态计算 |
| behavior_level | 行为等级 | 否 | 冷 / 温 / 热 |
| data_status | 数据状态 | 是 | 正常 / 无效 / 已合并 |
| remark | 备注 | 否 | |
| created_at | 入库时间 | 是 | |
| updated_at | 更新时间 | 是 | |
| created_by | 创建人 | 是 | 系统 / 人工 |

操作列固定「详情」。可用「列显示设置」隐藏部分列；序号、操作不可隐藏。

### 2.1 身份状态

`已注册未下单`、`已下单未开票`、`已绑定主体`、`已开票`。

### 2.2 数据状态

`正常`、`无效`、`已合并`。

### 2.3 行为等级（GEO 口径）

| 等级 | 分数 | 运营动作 |
| --- | --- | --- |
| 冷 | 10–20 | 刚注册或零星登录；销售暂不跟进，池内自动培育 |
| 温 | 21–45 | 浏览、点击 9.9 体验或填表；进线索池，SDR 初步触达 |
| 热 | 46 以上 | 进订单页、绑定主体、提交开票；销售立刻跟进 |

GEO 计分（按产线）：注册+授权手机号+同意协议 +10；登录一次 +2；点击「9.9元体验」+10；进入订单页 +15；绑定主体 +20；提交开票 +10。

### 2.4 筛选

按主表常用字段筛选，条件之间为且：

联系人ID、官网账号ID、手机号、客户主体名称、联系人姓名、邮箱（包含匹配）；来源渠道、来源详情（联动）、意向产品线、已购产品线、身份状态、行为等级、数据状态（精确）；入库时间（日期闭区间）。

按钮：查询、重置、批量导入（原型占位）。分页每页 10 条。

## 3. 子表 → 详情内容

点「详情」打开弹窗，**只展示子表（完整轨迹）**，不重复列出主表字段。

标题：`行为轨迹 【{联系人ID}】` + 行为等级标签。

### 3.1 行为汇总

| 字段名 | 中文名 | 必填 | 说明 |
| --- | --- | --- | --- |
| first_login_at | 首次登录时间 | 否 | datetime |
| login_count | 登录次数 | 否 | 默认 0 |
| last_active_at | 最近活跃时间 | 否 | datetime |
| last_behavior | 最近关键行为 | 否 | 如：点击 9.9 体验 |
| key_event_count | 关键事件次数 | 是 | 默认 0，点击体验/发票等累计 |
| has_order | 是否下单 | 否 | 0 / 1，详情展示是/否 |
| order_count | 订单数 | 否 | |
| order_amount | 订单金额 | 否 | |
| invoice_status | 开票状态 | 否 | 未申请 / 申请中 / 已开票 |

### 3.2 行为轨迹

`behavior_track`（json）。每条必须带产品线，行为分按产线分开算。

详情表格列：序号、时间、产品线、行为、得分。

无数据：「暂无行为轨迹」。底部：关闭。

---

## 4. 验收清单

- [ ] 列表列对应主表字段，不含子表登录/下单/开票等字段
- [ ] 详情只展示子表汇总 + 行为轨迹，不重复主表档案
- [ ] 身份状态、行为等级（冷/温/热）、数据状态展示正确
- [ ] 来源渠道与来源详情联动；邮箱、姓名未绑主体时可空
- [ ] 行为轨迹每行带产品线；GEO 样例分数与冷温热档位一致
- [ ] 操作列仅「详情」

---

## 5. 非目标

- 不在列表切换启用/停用、不编辑、不改密、不删除
- 批量导入仅占位
- 不在本页维护渠道/产品线字典本身
- 客户管理仍为独立菜单
