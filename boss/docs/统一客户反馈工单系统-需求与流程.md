# 蜜度 BOSS · 统一客户反馈工单系统

> 版本：V1.1  
> 日期：2026-11-16  
> 适用对象：产品确认、客服/售后、研发对接  
> 原型入口：`ticket.html`  
> 桌面单文件：`蜜度客户反馈工单.html`（样式与脚本已内联，可直接用浏览器打开）  
> 本地预览：在仓库根目录执行 `python3 -m http.server 8765 --bind 127.0.0.1`，访问 http://127.0.0.1:8765/ticket.html

**V1.1 相对 V1.0：** 提报拆成客户 / 销售 / 客服三个独立页面；产品项目改为分组单选；销售渠道仅蜜度官网、企微客户群；企微群名称仅在选企微客户群时显示且必填；列表增加反馈角色，反馈负责人为首个处理人；客服按联系电话或账号匹配客户；SLA 与反馈阶段按当前原型口径。

---

## 1. 背景与目标

把多渠道客户反馈纳入统一工单，跟踪处理效果并回收满意度评价。

**三统一：**

1. **统一入口、统一工单**：客户、销售、客服三条填写路径分别进线，工单落入 BOSS。日常沟通在智齿（在线/电话）等渠道完成，工单字段在智齿侧按蜜度表单记录后同步到 BOSS；BOSS 是工单主库。
2. **统一 SLA**：入库后 2 小时内完成首响。首响动作含完结、挂起、转工单、转销售；跟进不算首响。未首响阶段仍为待处理。客服处理按 2 小时倒数，转工单或转销售按 72 小时倒数。挂起不停表。
3. **统一评价回传**：客服确认完结后，按来源渠道原路发送「工单已完结」和满意度调查。详细完结内容只留在内部。

## 2. 渠道与操作端

| 渠道 | 进线入口 | 日常沟通操作端 | 工单主数据 | 评价原路回传 |
| --- | --- | --- | --- | --- |
| 电话 | 智齿来电 | 智齿 | BOSS 统一工单 | 通话终止后智齿自动拨号；若走工单，短信发送完结通知和评价链接 |
| 在线咨询 | 智齿会话 | 智齿 | BOSS 统一工单 | 会话结束后立即 · 聊天窗口弹窗 |
| 企微 1v1 | 企微私聊 | 智齿 | BOSS 统一工单 | 工单完结后 · 企微消息卡片 |
| 邮箱 | 客服邮箱 | 智齿 | BOSS 统一工单 | 工单已解决后 · 邮件 + 评价链接 |
| 企微客户群 | 客户群消息 | 智齿 | BOSS 统一工单 | 工单完结后 · 企微群发评价卡片 |
| 产品支持群 | 产品支持群 | 智齿 | BOSS 统一工单 | 客服交付解决方案后 · 企微 1v1 / 客户群推送 |
| 蜜度官网 | 官网表单 | 智齿 / BOSS 客户填写页 | BOSS 统一工单 | 工单完结后 · 邮件 / 短信评价链接 |

**原则：**

- 各渠道统一使用智齿收集工单，操作端打开智齿界面提交，再由智齿同步到 BOSS。
- BOSS 是唯一工单主库；智齿工单号、会话 ID 等作为外部关联键。
- 客户匹配在 BOSS 侧完成：客服按联系电话或账号匹配客户档案。

## 3. 端到端流程

```
【客户】
    ├─ 企微群反馈问题 → 销售/客成 → 销售填写反馈
    ├─ 蜜度官网反馈问题 → 客户填写反馈
    └─ 在线咨询 / 企微1V1 / 电话 / 邮箱 / 企微客户群 / 产品支持群
           │
           ▼
         【客服】验证能否立即解决
           ├─ 是 → 【满意度评价】
           └─ 否 → 【客服填写反馈】→ 同步到 BOSS 客户反馈工单
                        │
                        ▼
              【客服处理 · 待处理 / 处理中】
                        │
           ├─ 转工单 → 内部产研（72h）
           ├─ 转销售 → 问题日志（72h）
           └─ 挂起 → 处理中，不停表
                        │
                        ▼
              【待确认完结 / 客服确认完结】
                        │
                        ▼
                   【满意度评价 → 回传存档】
```

### 3.1 反馈阶段

| 反馈阶段 | 含义 |
| --- | --- |
| 待处理 | 已入库，尚未首响。超时未首响仍留在待处理，列表不展示「超时未首响」标签 |
| 处理中 | 已首响；挂起、转销售、转工单后也进入处理中 |
| 待确认完结 | 产研或处理结论待客服确认 |
| 已完结 | 客服确认关闭 |
| 超时完结 | 超时后关单 |

首响：完结、挂起、转工单、转销售。跟进不是首响。

内部状态（列表「内部状态」列，与反馈阶段并列）：未转出、已转销售、内部处理中、工单转回、内部工单完结等。同时存在转工单与转销售时，以内部工单内容为准。

### 3.2 SLA 与剩余时间

| 场景 | 时限 | 说明 |
| --- | --- | --- |
| 客服处理（未转出） | 2 小时 | 从入库起算 |
| 转工单 / 转销售 | 72 小时 | 从转出起算 |
| 挂起 | — | 不停表 |

- 未超时：显示「还剩 N 小时」，按小时向上取整，最少 1。
- 已超时：显示「已超时 N 小时」，按小时向上取整，最少 1。
- 已完结 / 超时完结：剩余时间列显示灰色完结时间（取 `closedAt` 或 `statusAt`）。

原型使用 `CATEGORY_GROUPS`（大类 + 可选子类）：

| 问题大类 | 问题子类 |
| --- | --- |
| 数据类 | 数据清洗类、数据采集类 |
| 产品类 | 需求反馈、使用与账号、配置与方案、数据与统计 |
| 联系商务 | 申请试用、催联系、找对接人 |
| 账号问题 | 账号类问题 |
| 产品需求反馈 | — |
| 法务/市场、宣传 | — |
| 客户临时需求 | — |
| 投诉类 | 投诉员工/服务 |

客服填写页：问题大类必填；有子类时子类必填。客户 / 销售填写页可不填分类，由后续客服或系统补充。

## 5. 三个填写页面

三个页面独立入口，不在同一页切换角色。

### 5.1 客户填写反馈

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 产品项目 | 是 | 分组单选，见 5.4 |
| 问题详情 | 是 | 可粘贴文字和图片 |
| 附件 | 否 | 可多文件，单文件 ≤ 10MB |
| 联系人姓名 | 是 | 放在联系方式区第一项 |
| 单位全称 | 否 | |
| 客户账号 | 否 | |
| 邮箱 | 否 | |

- 反馈渠道固定为蜜度官网。
- 不收集联系电话（登录后由手机号识别）。
- 提交类型：客户提交。

### 5.2 销售填写反馈

**A. 受理信息**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 提交人（销售） | 是 | 取当前登录账号，只读 |
| 客户联系方式 | 是 | 占位提示 `13812341234` |
| 反馈渠道 | 是 | 仅：蜜度官网、企微客户群 |
| 企微群名称 | 条件必填 | 仅当渠道=企微客户群时显示且必填 |

**B. 客户信息**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 客户ID | 是 | 6 位数字 |
| 线索ID | 否 | 2 开头的 6 位数字 |
| 客户名称 | 是 | |
| 账号 | 是 | |

**C. 问题分类**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 产品项目 | 是 | 分组单选 |
| 问题描述（客户原话） | 是 | 不改写；客服侧只读展示 |
| 附件 | 否 | |
| 销售补充说明 | 否 | 不覆盖客户原话，放在最下 |

提交类型：销售提交。转销售不改写工单上的反馈负责人。

### 5.3 客服填写反馈（含 H5）

PC 与 H5 同一套字段与显隐规则。

**A. 反馈人信息**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 业务类型 | 是 | 售前工单 / 售后工单 |
| 反馈渠道 | 是 | 电话、在线咨询、企微1v1、邮箱、企微客户群、产品支持群、蜜度官网 |
| 企微群名称 | 条件必填 | **仅当渠道=企微客户群时显示且必填**（H5 与 PC 一致；其他渠道不出现该字段） |
| 产品项目 | 是 | 分组单选 |
| 联系电话 | 否 | 可用于匹配客户 |
| 单位全称 | 否 | |
| 账号 | 否 | 可用于匹配客户 |
| 邮箱 | 否 | |
| 联系人 | 否 | |

提交后按联系电话或账号匹配客户档案；两者同时有值时须指向同一客户。

**B. 问题分类**：问题大类、问题子类（有则必填）、紧急度（P0 紧急 / P1 高 / P2 中 / P3 低）、问题详情、附件。  
**C. 内部备注**：选填，不对客户展示。

提交类型：客服提交。

### 5.4 产品项目（分组单选）

客户 / 销售 / 客服三个填写页的产品项目，统一为分组按钮单选（点选即填入并收起）：

| 分组 | 选项 |
| --- | --- |
| 智能检索 | 舆情通、索骥、城感通、数咖 |
| 智能校对 | 校对通、新媒通、安巡通 |
| 智能办公 | 模力通 |
| 其他 | 知知通、文稿通、版权通、品誉通、数察通DataQ、云能力、蜜度官网 |

列表筛选与详情编辑仍可用普通下拉，取值集合与上表一致。

## 6. 客户反馈工单列表

列表名称：**客户反馈工单**。

**列顺序：**

客户反馈ID、客户ID、客户类型、业务类型、产品项目、反馈渠道、问题大类、风险等级、反馈阶段、剩余时间、**反馈角色**、**反馈负责人**、内部状态、处理结果、满意度、操作。

| 字段 | 说明 |
| --- | --- |
| 业务类型 | 售前工单 / 售后工单；列宽收紧，与产品项目相邻 |
| 产品项目 | 列表展示优先取客户账号对应产品；无则用工单上的产品项目 |
| 反馈角色 | 客户 / 销售 / 客服，由提报类型映射：客户提交→客户，销售提交→销售，客服提交→客服。放在反馈负责人前一列 |
| 反馈负责人 | 第一个处理该工单的人（`firstHandler`）；转销售不改写该字段 |
| 反馈阶段 | 纯文本：待处理、处理中、待确认完结、已完结、超时完结 |
| 客户类型 | 直销、强国、代理、内部、其他 |
| 部门 | 工单所属部门；转办不改变部门 |

列表不展示「客户账号」列。右上角指标按当前筛选计算：完结率、平均完结时长、平均满意度、首次解决率。

行内操作：详情、跟进、挂起、申请升级、转工单、转销售、确认完结。确认完结可新开页签，处理人可直接确认完结；对外话术屏蔽手机号。

## 8. 评价回传闭环

| 渠道 | 触发时机 | 触发方式 |
| --- | --- | --- |
| 电话 | 通话终止后 | 客服外呼 / AI 自动外呼 |
| 在线咨询 | 会话结束后立即 | 聊天窗口弹窗 |

| 企微客户群 | 工单完结后 | 企微群发评价卡片 |
| 产品支持群 | 客服交付解决方案后 | 企微 1v1 / 客户群推送 |
| 蜜度官网 | 工单完结后 | 邮件 / 短信评价链接 |

满意度：红 / 黄 / 绿。任一项低于 3 星或填写了建议标红；有一项 3 星标黄；两项均 ≥ 4 星且无建议标绿。

## 9. 与智齿打通要点

- 客服在智齿记录工单，字段对齐蜜度客服填写页（业务类型、反馈渠道、产品项目、紧急度、企微群名称等自定义字段）。
- 工单信息推送同步到 BOSS；首次同步锁定反馈负责人（首个处理人）。
- 客户匹配、SLA、内部状态、反馈阶段留在 BOSS，不以智齿工单状态为准。
- 企微群名称在智齿侧无法按渠道条件必填时，可配置为选填，由 BOSS / 客服规范约束；原型侧仅在渠道=企微客户群时展示并校验必填。

---

## 10. 验收标准（产品向）

1. 客户 / 销售 / 客服三个填写页独立可进，字段与必填规则符合第 5 节。  
2. 产品项目为分组单选；销售渠道仅蜜度官网、企微客户群。  
3. 客服 PC 与 H5：仅选企微客户群时出现企微群名称且必填。  
4. 列表含反馈角色（客户/销售/客服），位于反馈负责人前；反馈负责人为首个处理人。  
5. 首响与阶段、剩余时间计算符合第 3 节；挂起不停表。  
6. 确认完结可新开页签；对外话术不含手机号。  
7. `蜜度客户反馈工单.html` 可脱离 `vendor/` 单独打开，行为与 `ticket.html` 一致。
