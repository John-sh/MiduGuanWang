# 蜜度 BOSS · 统一客户反馈工单系统

> 版本：V1.0  
> 日期：2026-09-24  
> 适用对象：产品确认、客服/售后、研发对接  
> 原型入口：`ticket.html`  
> 关联现状：外部反馈列表（图一）、评价触发渠道表（图二）

---

## 1. 背景与目标

公司需要把多渠道客户反馈纳入统一工单，跟踪处理效果并回收满意度评价。现状是：

| 现状 | 说明 |
| --- | --- |
| BOSS 外部反馈列表 | 主要承接官网等外部反馈，字段偏「登记」，处理人/日志/时长/方案/工单/FAQ 多为空 |
| 智齿（Sobot） | 客服对外在线咨询与电话，可建单、可做满意度调查，需与内部工单打通 |
| 企微 | 私聊 / 客户群 / 产品支持群在企微端操作，需回写内部工单 |
| 评价分散 | 各渠道评价触发时机与方式不同，结果未统一回写 |

**最终目标（三统一）：**

1. **统一入口、统一工单**：客户有三条进线。企微群反馈交给销售或客成，进入官网统一提报页面。蜜度官网反馈直接进入同一页面。在线咨询、企微1V1、电话、邮箱、企微客户群先到客服，能立即解决的进入满意度评价，不能解决的再提报工单。
2. **统一 SLA**：所有工单执行「2 小时响应、24 小时回复、72 小时完结」，超时自动升级，并把剩余时长同步给客户。
3. **统一评价回传**：客服确认完结后，按来源渠道原路回复固定话术「工单已完结」，同时发送满意度调查。详细完结内容只留在内部。

整套环节：**客户进线 → 提报工单（官网统一一页面）→ 客服处理并确认问题 → 产研处理 → 待确认完结 → 客服确认完结 → 满意度评价 → 评价回传并存档**。能立即解决的，从客服验证直接进入满意度评价。产研超时则工单升级、转办督办，再回到产研处理。评价回传后回到客户。

## 2. 渠道与操作端

| 渠道 | 进线入口 | 日常沟通操作端 | 工单主数据 | 评价原路回传 |
| --- | --- | --- | --- | --- |
| 电话 | 智齿来电 | 智齿 | BOSS 统一工单 | 通话终止后智齿自动拨号；若走工单，短信发送完结通知和评价链接 |
| 在线咨询 | 智齿会话 | 智齿 | BOSS 统一工单 | 会话结束后立即 · 聊天窗口弹窗 |
| 企微 1v1 | 企微私聊 | 企微 | BOSS 统一工单 | 工单完结后 · 企微消息卡片 |
| 邮箱 | 收件箱接入 | BOSS / 邮件客户端 | BOSS 统一工单 | 工单已解决后 · 邮件 + 评价链接 |
| 企微客户群 | 企微群消息 | 企微 | BOSS 统一工单 | 工单完结后 · 企微群发评价卡片 |
| 产品支持群 | 企微支持群 | 企微 | BOSS 统一工单 | 客服交付解决方案后 · 企微 1v1 / 客户群推送 |
| 蜜度官网 | 官网表单（现有外部反馈） | BOSS | BOSS 统一工单 | 工单完结后 · 邮件 / 短信评价链接 |

**原则：**

- 在线咨询、电话：**在智齿操作**，事件通过 API / Webhook 同步到 BOSS。
- 企微私聊与群聊：**在企微端操作**，通过企微应用 / 机器人 / 侧边栏回写 BOSS。
- BOSS 是**唯一工单主库**；智齿工单号、企微会话 ID、邮件 Message-ID 作为外部关联键。

    └─ 在线咨询 / 企微1V1 / 电话 / 邮箱 / 企微客户群

           │

    【验证问题，是否能立即解决】

           └─ 否 → 【提报工单 · 官网统一一页面】
                        │
                        ▼
              【客服处理工单，验证问题并确认问题】
                        │
                        ▼
              【流转进入内部系统，产研处理工单】◀──────┐
                        │                              │
                        ▼                              │
              【产研完结工单，工单变为待确认完结】       │
                        │                              │
                        ├─ 超时 → 【工单升级，转办督办】─┘
                        ▼
              【客服验证问题，确认工单完结】
                        │
                        ▼
                   【满意度评价】
                        │
                        ▼
              【评价回传，工单系统存档】

### 3.1 状态机

| 状态 | 含义 | 谁可以变更 | 典型动作 |
| --- | --- | --- | --- |
| 新增 | 已建单，待认领/待首响 | 系统 / 处理人 | 认领、自动分派 |
| 处理中 | 已首响，内部处理中 | 处理人 | 回复、补充信息、协同 |
| 已升级 | SLA 超时或人工升级 | 系统 / 主管 | 企微督办推送给上级 |
| 待确认完结 | 产研说明已回传，等待客服确认 | 处理人提交进入 | 详细说明仅内部可见 |
| 待销售补充 | 客户ID、线索ID或渠道不足，无法原路回复 | 系统退回 | 退回销售补齐后再进入客服处理 |
| 已完结 | 客服已确认关闭 | **客服** | 对外只发「工单已完结」，并发送满意度调查 |
| 已评价 | 评价已回写 | 系统 | 复盘、FAQ |

完结权限：客服确认完结，并填写产研传回的详细说明。创建人、客户、处理人不能代替客服关单。对外不展示详细完结内容。满意度调查发出后 48 小时仍未评价，评价状态记为已超时未评，工单保持已完结。

客户信息：不强制收集手机号。回复靠来源渠道原路返回。客户ID 下可以有多个联系人，线索ID 唯一，两者都要有，才能精准回复。已有线索不重复创建；没有线索时退回销售确认是否新建。反馈问题若客户状态为 MQL，沿用已有线索，不另建一条。

### 3.2 SLA 规则

| 节点 | 标准 | 起算点 | 超时动作 |
| --- | --- | --- | --- |
| 响应 | 2 小时内首次响应 | 建单时间 | 黄灯预警，企微督办当前处理人 → 超时升级并企微推送其上级 |
| 回复 | 24 小时内有效回复（含方案或明确下一步） | 建单时间 | 橙灯预警，企微督办当前处理人 → 超时升级并企微推送组负责人 |
| 完结 | 72 小时内完结（已解决/已关闭） | 建单时间 | 红灯预警，企微督办当前处理人 → 超时升级并企微推送售后主管 |

- 客户等待补充信息期间可**暂停 SLA**（需记录原因）。
- 工作时间口径：默认自然时（可配置工作日历，原型先按自然时）。
- 列表与详情展示：剩余时间、是否超时、升级记录。

## 4. 问题分类

问题分类按大类归口。具体问题在提报和改分类时选择，分类管理只保留范围。

| 编码 | 问题大类 | 范围 |
| --- | --- | --- |
| C01 | 产品故障/数据问题 | 数据缺失、白屏、导出、预警和加载异常 |
| C02 | 产品咨询/功能咨询 | 安装配置、API、资料下载和报告领取 |
| C03 | 需求反馈 | 新能力、套餐和个人用户需求 |
| C04 | 投诉员工/服务 | 联系不上、发票、收费和人员投诉 |
| C05 | 账号问题 | 登录、密码、改绑和注销 |
| C06 | 商务/询价/对接/到期/注册/催联系 | 询价、找人、到期、注册和催办 |
| C07 | 推销/法务/市场/宣传 | 侵权、采访、敏感内容和展会 |

| C10 | 代理商 | 查询代理商 |

建单时按大类初分，具体问题可在处理中修改。产品故障类可同步研发；需求反馈可进入需求池。列表和看板按大类筛选。

## 5. 统一工单字段

字段先于页面。工单列表名称为客户反馈工单，按线索id、客户id、客户负责人、部门、提交类型、提交人、反馈渠道、产品项目、联系方式、客户状态、账号是否在有效期、入库时间、问题分类、问题详情、风险等级、工单阶段、首次响应时间、是否首次解决、完结剩余时间、当前处理人、处理结果、满意度、操作、更多排列。账号是否在有效期紧跟客户状态，取值为是或否。是否首次解决单独存 Y/N，并作为筛选项。问题只保留一层分类，没有二级分类。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 线索id | 否 | 列表保留。提报页不填写 |
| 客户id | 否 | 列表保留。提报页不填写，客户信息以账号为准 |
| 提交类型 | 是 | 客户提交 / 销售提交 / 客服提交。页面顶部切换 |
| 提交人 | 否 | 实际提交工单的人 |
| 反馈渠道 | 销售、客服必填 | 客户提报不选择。销售和客服选择渠道 |
| 产品项目 | 是 | 舆情通、校对通、模力通 |
| 账号 | 是 | 提报时客户信息的唯一值。客户名称、客户ID、客户状态、线索ID不在提报页填写 |
| 联系方式 | 视渠道 | 反馈渠道为电话、在线咨询、邮箱时必填 |
| 部门 | 否 | 工单所属部门。列表保留，提报页不填写 |
| 客户负责人 | 否 | 列表保留。提报页不填写 |
| 客户状态 | 否 | 列表保留。正式客户、初次接触、上门拜访、开通试用、产品培训、提案报价、协议商谈、客户交接、客户使用、客户续费、客户失败、客户失败-新签、客户失败-续签。提报页不填写 |
| 账号是否在有效期 | 否 | 是 / 否 |
| 入库时间 | 是 | 工单进入列表的时间 |
| 问题分类 | 是 | 产品故障、数据问题、产品/功能咨询、账号问题、联系商务、投诉、其他。没有二级分类 |
| 问题详情 | 是 | 问题描述，支持粘贴文字和图片 |
| 附件 | 否 | 提报时可上传多个文件，单个不超过 10MB，随工单保存 |
| 风险等级 | 否 | P0-紧急（重大舆情/系统宕机）、P1-高（数据严重遗漏/投诉）、P2-中（配置问题）、P3-低（常规咨询） |
| 工单阶段 | 是 | 待处理（2小时）、处理中（72小时）、退回/驳回、挂起、待确认完结、已完结、超时完结。退回给提交人；挂起用于等研发或业务审批 |
| 首次响应时间 | 否 | 第一次有效响应的时间 |
| 是否首次解决 | 否 | Y / N。列表字段，也可筛选 |
| 完结剩余时间 | 是 | 未完结显示剩余小时；已完结、超时完结显示完结时间 |
| 当前处理人 | 否 | 客服或被转办的负责人 |
| 处理结果 | 否 | 内部反馈回传的结果 |
| 满意度 | 否 | 红 / 黄 / 绿。任一项低于 3 星，或填写了建议，标红；有一项是 3 星标黄；两项都在 4 星及以上且没有建议，标绿 |
| 您的建议与意见 | 否 | 满意度调查的第三项，输入框。有内容即把工单满意度标红 |
| 内部完结内容 | 完结时必填 | 产研传回的详细说明，仅内部可见 |
| 对外话术 | 系统生成 | 固定为「工单已完结」，不带详细内容 |
| 原路回复 | 系统生成 | 企微私聊回企微，群聊回群内，在线咨询回会话。电话未建单由智齿在通话终止后自动拨号评价；已建工单则短信发送完结通知和评价链接 |

手机号不是必填。提报时用账号识别客户。各渠道都在智齿界面提交，再同步到 BOSS。

处理日志、优先级、SLA 节点仍记在工单上。列表右上角四个指标按当前筛选结果计算：完结率是已完结、超时完结占筛选总数；平均完结时长是这些完结工单从入库到完结的平均小时；平均满意度是已评分的平均分；首次解决率按是否首次解决为 Y 的完结工单计算。

列表可按首次解决、工单满意度筛选。工具栏有开通试用，登记客户ID、账号和产品后，把对应客户状态改为开通试用。行内操作为添加跟进记录、挂起、申请升级（给上级）、转工单（新开页面）、确认完结。更多里是详情，以及给客户看的跟踪进度摘要。提报工单只收集账号作为客户唯一值。我的工单里的创建工单直接进入提报工单页面。

## 8. 与智齿 / 企微打通要点

### 8.1 智齿

- 进线事件（来电振铃结束 / 会话建立）→ BOSS 建单或关联已有单。  
- 智齿侧建单 / 关单 / 转派 → 双向同步状态与处理人。  
- 智齿满意度结果 → 通过工单号或通话记录映射回写 BOSS。  
- 电话评价触发方式为客服外呼/AI自动外呼。
- 各渠道都在智齿界面提交工单，智齿再同步到 BOSS。官网和邮箱先与智齿打通。

### 8.2 企微

- 私聊 / 群聊通过「建单」按钮或关键词机器人生成工单。  
- 工单卡片展示编号、SLA 倒计时、认领人。  
- **转办督办**：流转确定负责人后，向对应负责人推送企微消息。转办通知新负责人接手；督办在 SLA 预警、超时或转办后未响应时再次推送，仍超时则推送给其上级。消息带工单号、客户、分类、SLA 剩余时间和处理入口。  
- 完结后推送评价卡片；回调 URL 写回 BOSS。

### 8.3 官网反馈

- 现有外部反馈提交接口改为直接落统一工单（渠道=官网反馈）。  
- 历史「客户问题 ID」保留为兼容字段。

## 9. 验收标准（产品向）

1. 客服不能当场解决的进线，七渠道均可在 BOSS 看到带渠道标签的工单。能当场解决的只答疑回复，不建单。  
2. 建单即启动 SLA；超时产生升级记录，并通过企微消息督办对应负责人。转办后，新负责人收到企微转办消息。  
3. 完结后按渠道规则触发评价；评价结果出现在工单详情并关联客服。  
4. 问题可按一、二级分类筛选与统计。  
5. 智齿 / 企微外部单号可在详情中跳转或复制关联。
