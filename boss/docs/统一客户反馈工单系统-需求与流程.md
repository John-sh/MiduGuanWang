# 蜜度 BOSS · 统一意见反馈工单系统

> 版本：V1.3  
> 日期：2026-11-19  
> 适用对象：产品确认、客服/售后、研发对接  
> 原型入口：`ticket.html`  
> 桌面单文件：`蜜度客户反馈工单.html`（样式与脚本已内联，可直接用浏览器打开）  
> 本地预览：在仓库根目录执行 `python3 -m http.server 8765 --bind 127.0.0.1`，访问 http://127.0.0.1:8765/ticket.html

**V1.3 相对 V1.2：** 客服填写页只按账号匹配客户详情。联系电话只记录客户提供的号码，不参与客户匹配。

**V1.2 相对 V1.1：** 官网「反馈」先登录，员工账号进入销售填写页，普通账号进入客户填写页；客服填写页单独制作，上线后单独发给客服。满意度调查免登录，按 URL 中的工单 id 拉取简要并回写该工单评价。产品项目、问题大类、问题子类改为接口下发，产品项目接口按分组返回。

**V1.1 相对 V1.0：** 提报拆成客户 / 销售 / 客服三个独立页面；产品项目改为分组单选；销售渠道仅蜜度官网、企微客户群；企微群名称仅在选企微客户群时显示且必填；列表增加反馈角色，反馈负责人为首个处理人；客服按联系电话或账号匹配客户；SLA 与反馈阶段按当前原型口径。

## 1. 背景与目标

把多渠道意见反馈纳入统一工单，跟踪处理效果并回收满意度评价。

**三统一：**

1. **统一入口、统一工单**：客户、销售、客服三条填写路径分别进线，工单落入 BOSS。日常沟通在智齿（在线/电话）等渠道完成，工单字段在智齿侧按蜜度表单记录后同步到 BOSS；BOSS 是工单主库。
2. **统一 SLA**：按紧急度分开计算首次响应和工单处理时间。工单流转进来紧急度默认为 P1 高，客服填写或跟进时可以改成 P0–P3。未定级不能挂起、申请升级、转工单、转销售或确认完结。首响动作是跟进、挂起、转工单、转销售。首响后按同一紧急度计算处理时间。挂起不停表，转工单和转销售不重新计时。
3. **统一评价回传**：客服确认完结后，按来源渠道原路发送「工单已完结」和满意度调查。详细完结内容只留在内部。

## 2. 渠道与操作端

| 渠道 | 进线入口 | 日常沟通操作端 | 工单主数据 | 评价原路回传 |
| --- | --- | --- | --- | --- |
| 电话 | 智齿来电 | 智齿 | BOSS 统一工单 | 通话终止后智齿自动拨号；若走工单，短信发送完结通知和评价链接 |
| 在线咨询 | 智齿会话 | 智齿 | BOSS 统一工单 | 会话结束后立即 · 聊天窗口弹窗 |
| 企微 1v1 | 企微私聊 | 智齿 | BOSS 统一工单 | 工单完结后 · 企微消息卡片 |
| 邮箱 | 客服邮箱 | 智齿 | BOSS 统一工单 | 工单已解决后 · 邮件 + 评价链接 |
| 企微客户群 | 客户群消息 | 智齿 | BOSS 统一工单 | 工单完结后 · 企微群发评价卡片 |
| 产品支持群 | 产品支持群 | 智齿 | BOSS 统一工单 | 客服交付解决方案后 · 企微 1v1 / 客户群推送 |
| 蜜度官网 | 官网表单 | 智齿 / BOSS 客户填写页 | BOSS 统一工单 | 工单完结后 · 邮件 / 短信评价链接 |

**原则：**

- 各渠道统一使用智齿收集工单，操作端打开智齿界面提交，再由智齿同步到 BOSS。
- BOSS 是唯一工单主库；智齿工单号、会话 ID 等作为外部关联键。
- 客户匹配在 BOSS 侧完成：客服按账号匹配客户档案。联系电话只记录客户提供的号码，不参与匹配。

## 3. 端到端流程

```
【客户】
    ├─ 企微群反馈问题 → 销售/客成 → 销售填写反馈
    ├─ 蜜度官网点击「反馈」→ 登录
    │     ├─ 员工账号 → 销售填写反馈
    │     └─ 普通账号 → 客户填写反馈
    └─ 在线咨询 / 企微1V1 / 电话 / 邮箱 / 企微客户群 / 产品支持群
           │
           ▼
         【客服】验证能否立即解决
           ├─ 是 → 【满意度评价】
           └─ 否 → 【客服填写反馈】→ 同步到 BOSS 意见反馈工单
                        │
                        ▼
              【客服处理 · 待处理 / 处理中】
                        │
           ├─ 转工单 → 内部产研（72h）
           ├─ 转销售 → 问题日志（72h）
           └─ 挂起 → 处理中，不停表
                        │
                        ▼
              【待确认完结 / 客服确认完结】
                        │
                        ▼
                   【满意度评价 → 回传存档】
```

### 3.1 反馈阶段

| 反馈阶段 | 含义 |
| --- | --- |
| 待处理 | 已入库，尚未首响。列表不展示「超时未首响」标签 |
| 处理中 | 已首响；跟进定级、挂起、转销售、转工单后进入处理中 |
| 待确认完结 | 产研或处理结论待客服确认 |
| 已完结 | 客服确认关闭 |
| 超时完结 | 超时后关单 |

首响：跟进、挂起、转工单、转销售。未定级时只能跟进（以及查看详情）。

内部状态（列表「内部状态」列，与反馈阶段并列）：未转出、已转销售、内部处理中、工单转回、内部工单完结等。同时存在转工单与转销售时，以内部工单内容为准。

### 3.2 SLA 与剩余时间

工单流转进来紧急度默认为 P1 高（首次响应 60 分钟，处理 48 小时）。客服填写页和跟进弹窗可以改成 P0–P3。没有紧急度时，剩余时间显示「未定级」，除详情和跟进外的操作按钮不可用。

| 紧急度 | 首次响应 | 工单处理 |
| --- | --- | --- |
| P0 紧急 | 30 分钟 | 24 小时 |
| P1 高 | 60 分钟 | 48 小时 |
| P2 中 | 2 小时 | 72 小时 |
| P3 低 | 2 小时 | 72 小时 |

- 未首响：从入库起按首次响应时限倒数。列表「首次响应时间」显示剩余时间「还剩 xx小时 xx分」，超时显示红色「超时 xx小时 xx分」。「剩余时间」同步显示「首响 还剩 xx小时 xx分」。
- 已首响：列表「首次响应时间」显示从录入时间到首次响应的时长。「剩余时间」从首次响应时间起按工单处理时限倒数，显示「处理 还剩 xx小时 xx分」。转工单、转销售不重新计时。
- 超时：显示「超时 xx小时 xx分」，颜色标红。时间按分钟向上取整。
- 挂起不停表。
- 已完结 / 超时完结：剩余时间列显示灰色完结时间（取 `closedAt` 或 `statusAt`）。

### 3.3 官网填写入口

填写反馈放在蜜度官网。用户点击官网「反馈」后先进入登录；登录完成后再按账号类型打开对应填写页。页面上不提供角色切换。

| 登录账号 | 进入页面 |
| --- | --- |
| 员工账号 | 销售填写反馈 |
| 普通账号 | 客户填写反馈 |

- 未登录点击「反馈」，只去登录，不打开填写页。登录成功后按上表进入，不再停在登录页。
- 员工账号与普通账号以登录账号类型为准。
- 客服填写反馈不挂在官网「反馈」按钮上。该页单独制作，上线后把链接单独发给客服使用。客服页仍保留 PC / H5 同一套字段。

## 4. 问题分类

问题大类、问题子类由接口下发，前端不写死选项。接口返回大类，以及每个大类下的子类；没有子类时子类列表为空。客服填写页、工单详情和列表筛选用这份数据。

当前分类口径如下，接口按此结构返回：

| 问题大类 | 问题子类 |
| --- | --- |
| 数据类 | 数据清洗类、数据采集类 |
| 产品类 | 需求反馈、使用与账号、配置与方案、数据与统计 |
| 联系商务 | 申请试用、催联系、找对接人 |
| 账号问题 | 账号类问题 |
| 产品需求反馈 | — |
| 法务/市场、宣传 | — |
| 客户临时需求 | — |
| 投诉类 | 投诉员工/服务 |

客服填写页：问题大类必填；有子类时子类必填。客户 / 销售填写页可不填分类，由后续客服或系统补充。

## 5. 三个填写页面

客户填写页、销售填写页从官网「反馈」进入，规则见 3.3。客服填写页独立发放，不从该按钮进入。三个页面之间不切换角色。

### 5.1 客户填写反馈

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 产品项目 | 是 | 分组单选，见 5.4 |
| 问题详情 | 是 | 可粘贴文字和图片。提示语为：您好，请描述您遇到的问题，建议包含页面或功能、问题现象、预期结果 |
| 附件 | 否 | 可多文件，单文件 ≤ 10MB |
| 是否接受回访 | 是 | 放在反馈内容模块最后。是 / 否。工单详情展示 |
| 联系人姓名 | 否 | 联系方式区第一项 |
| 客户账号 | 否 | |
| 联系电话 | 否 | 放在客户账号之后、邮箱之前。默认显示当前登录手机号，中间 4 位打码。输入框后有「+」，用于新增接收工单结果的手机号 |
| 邮箱 | 否 | 放在联系电话右侧 |
| 单位全称 | 否 | |

- 反馈渠道固定为蜜度官网。
- 登录手机号写入工单联系电话；「+」新增的号码只作为结果通知电话，工单结果发给这些号码。
- 提交类型：客户提交。

### 5.2 销售填写反馈

**A. 受理信息**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 提交人（销售） | 是 | 取当前登录账号，只读 |
| 客户联系方式 | 是 | 占位提示 `13812341234` |
| 反馈渠道 | 是 | 仅：蜜度官网、企微客户群 |
| 企微群名称 | 条件必填 | 仅当渠道=企微客户群时显示且必填 |

**B. 客户信息**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 客户ID | 是 | 6 位数字 |
| 线索ID | 否 | 2 开头的 6 位数字 |
| 客户名称 | 是 | |
| 账号 | 是 | |

**C. 问题分类**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 产品项目 | 是 | 分组单选 |
| 问题描述（客户原话） | 是 | 不改写；客服侧只读展示。提示语与客户填写页的问题详情相同 |
| 附件 | 否 | |
| 是否接受回访 | 是 | 是 / 否。工单详情展示 |
| 销售补充说明 | 否 | 不覆盖客户原话，放在最下 |

提交类型：销售提交。转销售不改写工单上的反馈负责人。

### 5.3 客服填写反馈（含 H5）

PC 与 H5 同一套字段与显隐规则。

**A. 反馈人信息**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 业务类型 | 是 | 售前工单 / 售后工单 |
| 反馈渠道 | 是 | 电话、在线咨询、企微1v1、邮箱、企微客户群、产品支持群、蜜度官网 |
| 企微群名称 | 条件必填 | **仅当渠道=企微客户群时显示且必填**（H5 与 PC 一致；其他渠道不出现该字段） |
| 产品项目 | 是 | 分组单选 |
| 联系电话 | 否 | 只记录客户提供的联系号码，不参与客户匹配 |
| 单位全称 | 否 | |
| 账号 | 否 | 选填。填写后按账号匹配客户详情 |
| 邮箱 | 否 | |
| 联系人 | 否 | |

提交后只按账号匹配客户档案。账号能对应到唯一客户时，带出该客户的客户 ID、客户名称、客户类型、客户进度、客户负责人和部门。联系电话即使与档案中的号码一致，也不用来匹配。未填账号，或账号对不上客户时，工单仍可提交，客户信息留空。

**B. 问题分类**：问题大类、问题子类（有则必填）、紧急度（P0 紧急 / P1 高 / P2 中 / P3 低）、问题详情、是否接受回访（是 / 否，必填）、附件。问题详情提示语与客户、销售填写页相同。  
**C. 内部备注**：选填，不对客户展示。

提交类型：客服提交。

### 5.4 产品项目（分组单选）

客户 / 销售 / 客服三个填写页的产品项目，统一为分组按钮单选（点选即填入并收起）。选项由产品项目接口返回，接口里已经分好组，前端按返回的分组直接渲染，不再在页面里归类。

当前分组口径如下，接口按此结构返回：

| 分组 | 选项 |
| --- | --- |
| 智能检索 | 舆情通、索骥、城感通、数咖 |
| 智能校对 | 校对通、新媒通、安巡通 |
| 智能办公 | 模力通 |
| 其他 | 知知通、文稿通、版权通、品誉通、数察通DataQ、云能力、蜜度官网 |

列表筛选与详情编辑仍可用普通下拉，选项取自同一接口，把各分组下的项目摊平。单选，一次只能选一个产品项目。

## 6. 意见反馈工单列表

列表名称：**意见反馈工单**。

**列顺序：**

意见反馈ID、客户ID、客户类型、业务类型、产品项目、反馈渠道、问题大类、风险等级、反馈阶段、**首次响应时间**、剩余时间、**反馈角色**、**反馈负责人**、内部状态、处理结果、满意度、操作。

| 字段 | 说明 |
| --- | --- |
| 业务类型 | 售前工单 / 售后工单。列表与产品项目相邻，详情同样展示 |
| 产品项目 | 列表展示优先取客户账号对应产品；无则用工单上的产品项目 |
| 反馈角色 | 客户 / 销售 / 客服，由提报类型映射：客户提交→客户，销售提交→销售，客服提交→客服。列表放在反馈负责人前一列，详情同样展示 |
| 是否接受回访 | 填写页提交的是 / 否，详情展示 |
| 反馈负责人 | 第一个处理该工单的人（`firstHandler`）；转销售不改写该字段 |
| 反馈阶段 | 纯文本：待处理、处理中、待确认完结、已完结、超时完结 |
| 首次响应时间 | 放在剩余时间前。未跟进显示首次响应剩余时间，超时标红；已跟进显示录入时间到首次响应的时长 |
| 客户类型 | 直销、强国、代理、内部、其他 |
| 部门 | 工单所属部门；转办不改变部门 |

列表不展示「客户账号」列。筛选项中的紧急度按工单紧急度（P0–P3）过滤，不再用风险等级。反馈角色可筛客户、销售、客服。右上角指标按当前筛选计算：完结率、平均完结时长、平均满意度、首次解决率。

行内操作：详情、跟进、挂起、申请升级、转工单、转销售、确认完结。确认完结可新开页签，处理人可直接确认完结；对外话术屏蔽手机号。

## 8. 评价回传闭环

| 渠道 | 触发时机 | 触发方式 |
| --- | --- | --- |
| 电话 | 通话终止后 | 客服外呼 / AI 自动外呼 |
| 在线咨询 | 会话结束后立即 | 聊天窗口弹窗 |
| 企微 1v1 | 工单完结后 | 企微消息卡片 |
| 邮箱 | 工单已解决后 | 邮件 + 评价链接 |
| 企微客户群 | 工单完结后 | 企微群发评价卡片 |
| 产品支持群 | 客服交付解决方案后 | 企微 1v1 / 客户群推送 |
| 蜜度官网 | 工单完结后 | 邮件 / 短信评价链接 |

评价链接必须带该工单的 id。各渠道发出的满意度链接使用同一调查页。

### 8.1 满意度调查页

满意度调查页无需登录。打开链接即可评价，不跳转登录页。

1. 从 URL 读取工单 id（参数名 `id`）。
2. 用该 id 拉取工单简要并展示：反馈 ID、产品项目、完结说明。不展示内部备注和处理过程。
3. 用户提交的评价回写到这个工单 id 的评价，包括处理结果满意度、服务态度与响应速度、文字反馈。回写不依赖当前是否登录。
4. `id` 缺失、工单不存在时，不展示可提交表单，提示链接无效。该工单已有评价时，展示已提交结果，不再重复提交。

满意度：红 / 黄 / 绿。任一项低于 3 星或填写了建议标红；有一项 3 星标黄；两项均 ≥ 4 星且无建议标绿。

## 10. 与智齿打通要点

- 客服在智齿记录工单，字段对齐蜜度客服填写页（业务类型、反馈渠道、产品项目、紧急度、企微群名称等自定义字段）。
- 工单信息推送同步到 BOSS；首次同步锁定反馈负责人（首个处理人）。
- 客户匹配、SLA、内部状态、反馈阶段留在 BOSS，不以智齿工单状态为准。
- 企微群名称在智齿侧无法按渠道条件必填时，可配置为选填，由 BOSS / 客服规范约束；原型侧仅在渠道=企微客户群时展示并校验必填。

## 11. 验收标准（产品向）

1. 官网点击「反馈」先登录。员工账号进入销售填写页，普通账号进入客户填写页。客服填写页不从该按钮进入，上线后单独发给客服。  
2. 三个填写页字段与必填规则符合第 5 节。  
3. 产品项目为分组单选，分组和选项来自产品项目接口；销售渠道仅蜜度官网、企微客户群。  
4. 问题大类、问题子类来自分类接口，前端不写死。  
5. 客服 PC 与 H5：仅选企微客户群时出现企微群名称且必填。  
6. 列表含反馈角色（客户/销售/客服），位于反馈负责人前；反馈负责人为首个处理人。  
7. 流转进来默认 P1；未定级只能跟进。定级后按第 3.2 节分开计算首次响应和工单处理时间，超时红色显示到分钟；挂起不停表。  
8. 确认完结可新开页签；对外话术不含手机号。  
9. 满意度调查免登录。URL 带工单 id 时展示该工单简要，提交后评价回写到该工单。  
10. `蜜度客户反馈工单.html` 可脱离 `vendor/` 单独打开，行为与 `ticket.html` 一致。
