## 1. 项目概述

### 1.1 背景

客户在官网、小程序完成套餐购买并支付后，订单与开票信息进入 BOSS。运营、财务目前缺少一套统一、只读为主的后台能力，无法稳定完成以下工作：

1. 核对官网支付订单：购买内容、金额、支付、服务周期、开票进度、到账、权益用量。
2. 跟踪电子发票：开具进度、票面信息、到账情况、附件归档。

本项目在 BOSS 中建设 **线上订单**、**线上订单发票** 两个独立菜单页。数据同源（官网支付成功订单），职责分开，互不替代。

### 1.2 项目目标

| 目标 | 说明 |
| --- | --- |
| 订单可查、可核 | 运营能按订单编号、用户、套餐、时间等条件快速定位订单，并在详情中看全貌 |
| 发票可管、可追 | 财务能按开票状态、税号账户、金额进度管理发票，并归档电子发票附件 |
| 职责隔离 | 订单页看交易与权益；发票页看票面、到账与附件；敏感账号信息不铺在发票宽表上 |
| 计收开票闭环 | 有支付即进入开票管理视野；原则是「下单需谨慎，所有订单需计收开票」 |

### 1.3 产品原则

- 订单来源于官网 / 小程序支付成功同步，BOSS **不在列表上直接开票、退单、作废重开**。
- 一张发票可以对应多笔订单（同一抬头合并开票）。
- 用户名、账号、付款编号只在详情中按订单展示，不出现在发票列表。
- 发票号只在「线上订单发票」中维护与展示；订单详情开票信息表不展示发票号。

### 1.4 范围

**本项目包含**

- 线上订单：列表筛选、分页、详情（订单明细 / 开票信息 / 到账流水 / 累计权益总量 / 操作记录）
- 线上订单发票：列表筛选、统计面板、导出、详情（订单信息 / 发票信息 / 附件信息 / 操作记录）
- 附件上传、预览、下载、删除（仅发票模块）
- 菜单权限拆分、操作审计

**本项目不包含（非目标）**

- BOSS 内发起开票、退单、作废重下、作废重开
- 税控开具作业流（认领、开具、红冲）
- 线下合同订单、手工录入订单
- 客户自助开票门户改造

## 2. 用户与使用场景

| 角色 | 主要入口 | 典型场景 |
| --- | --- | --- |
| 运营 | 订单管理 / 线上订单 | 客户问「我买了什么、什么时候到期」；核对套餐、支付、权益是否到账 |
| 财务 / 开票运营 | 收支管理 / 线上订单发票 | 查待开票、导出开票信息、核对税号账户、上传电子发票 PDF |
| 系统 | 后台同步 | 官网支付成功后生成订单；用户提交开票后生成发票记录 |

两个菜单可分开授权，互不强制同时开通。

## 3. 业务关系

```
官网 / 小程序下单
        │
        ▼
   支付成功（微信 / 支付宝）
        │
        ├──────────────► 线上订单（一单一条）
        │                     ├ 订单明细
        │                     ├ 开票信息（可 0～N 条）
        │                     ├ 到账流水
        │                     ├ 累计权益总量
        │                     └ 操作记录
        │
        └──────────────► 线上订单发票（一张发票一条；可对应 1～N 笔订单）
                              ├ 订单信息（表格，一行一单）
                              ├ 发票信息（开票 / 收件 / 到账流水）
                              ├ 附件信息
                              └ 操作记录
```

关联键：

- 订单侧：`订单编号`（官网统一订单号）
- 发票侧：`发票号`（未开具可空）；详情通过 `orders[]` 挂多笔订单

**关系约定**

- 订单 : 发票 = N : 1（一张发票可挂多笔订单）。
- 未提交开票的订单：订单详情「开票信息」可为空。
- 订单作废后，关联发票状态按财务规则变为「已作废」；已开票是否红冲见文末待确认。

## 4. 公共字典与业务规则

### 4.1 订单状态

仅两种，**没有「退单」状态**。客户退款、重复购买等，订单状态记为「作废」。

| 值 | 含义 | 列表样式 |
| --- | --- | --- |
| 正常 | 有效订单 | 绿色标签 |
| 作废 | 已失效（含退款、作废重下等） | 灰色标签 |

### 4.2 开票状态

| 值 | 含义 | 列表样式 |
| --- | --- | --- |
| 待开票 | 已提交或应开，尚未进入开具 | 蓝色 |
| 开票中 | 已进入开具流程，尚未出票 | 橙色 |
| 已开票 | 已开具，通常已有发票号 | 绿色 |
| 已作废 | 发票作废 | 灰色；发票列表行弱化 |

流转：

```
（支付成功，用户提交开票）
        │
        ▼
     待开票 ──► 开票中 ──► 已开票
        │          │
        └──────────┴──► 已作废
```

- 已开票后作废：状态变为「已作废」，发票号可保留用于追溯。
- 列表不提供「作废重开」按钮。

### 4.3 单位属性

出现在**列表列、详情**，**不作为筛选项**。

| 值 | 开票信息要求 |
| --- | --- |
| 企业单位 | 需税号、注册地址/电话、开户行、银行账号等企业开票字段 |
| 非企业单位 | 抬头可为机构/项目部等；税号、地址、电话、开户行、账号按财务规则可空 |
| 个人 | 抬头为个人姓名；税号、地址、电话、开户行、账号可空 |

### 4.4 其他字典

| 字典 | 取值 |
| --- | --- |
| 支付方式 | 微信、支付宝 |
| 发票类型 / 开票类型 | 专票电子票、普票电子票（列表用「发票类型」，详情开票信息用「开票类型」，取值相同） |
| 附件类型 | 电子发票、开票资料、资质文件、开票申请、其他 |

### 4.5 金额与时间口径

| 名称 | 口径 |
| --- | --- |
| 单价 / 价格（总价） | 人民币，两位小数，千分位展示 |
| 订单总价 | 明细小计之和 |
| 开票金额 | 本次申请开具金额；合并开票时应等于关联订单金额合计 |
| 到账金额 | 已入账合计（退款为负时按流水汇总） |
| 未到账金额 | `max(开票金额 − 到账金额, 0)` |
| 下单 / 支付 / 开票提交 / 开票时间 | `YYYY-MM-DD HH:mm:ss` |
| 服务天数 | 服务终止日与开始日的间隔天数；终止日展示为 `YYYY-MM-DD（N天）` |

金额空值界面显示空，不当成 0；计算时按 0。

## 5. 功能需求一：线上订单

### 5.1 页面定位

运营查询官网支付订单，核对套餐、金额、支付、开票进度与权益用量。  
列表操作列 **仅「详情」**。

菜单位置：订单管理 / 线上订单。  
警示文案：`*下单需谨慎，所有订单需计收开票`。

### 5.2 列表筛选

| 筛选项 | 控件 | 匹配规则 | 备注 |
| --- | --- | --- | --- |
| 产品 | 下拉，可清空 | 精确 | 样例：蜜度GEO |
| 订单编号 | 文本 | 包含 | placeholder：官网统一订单号 |
| 套餐名称 | 文本 | 包含 | |
| 用户名 | 文本 | 包含 | 仅筛选，不作为列表列 |
| 账号（手机号） | 文本 | 包含 | 仅筛选，不作为列表列 |
| 发票抬头 | 文本 | 包含 | |
| 订单状态 | 下拉：正常 / 作废 | 精确 | 空=全部 |
| 下单时间 | 日期范围 | 按下单日期落在区间内 | |
| 服务开始日期 | 单日期 | `>=` 所选日期 | |
| 服务终止日期 | 单日期 | `<=` 所选日期 | |

按钮：查询、重置。分页：每页 10 条。

### 5.3 列表列

勾选、#、产品、订单编号、套餐名称、套餐描述、订购数量、单价、价格（总价）、服务开始日期、服务终止日期、下单时间、支付方式、单位属性、发票抬头、订单状态、操作（详情）。

**列表明确不出现**

- 发票号、开票状态、发票类型
- 用户名、账号、付款编号（详情页展示）

套餐描述过长时截断，hover 展示全文。

### 5.4 订单详情

标题：`订单详情 【{订单编号}】` + 订单状态标签。  
底部按钮：关闭。

**页头信息（始终展示）**

产品、订单编号、套餐名称、套餐描述、订购数量、单价、价格、服务开始/终止日期、下单时间、用户名、账号（手机号，可脱敏）、支付方式、付款编号、单位属性、发票抬头、订单状态。

若存在作废说明，页头下方展示：

`原订单（{originOrderNo}）作废，原订单金额：{金额}，原因：{voidRemark}`

**Tab**

| Tab | 内容 |
| --- | --- |
| 订单明细 | 一行一条购买项：产品、套餐、数量、单价、小计、服务周期 |
| 开票信息 | 开票进度与购方税号信息；**不含发票号、发票类型、公司**；无数据时「暂无开票信息」 |
| 到账流水 | 到账时间、到账金额（支持负数）、备注；无数据时「暂无到账流水」 |
| 累计权益总量 | 上卡片 + 下表格：累计总量、已用、剩余、说明 |
| 操作记录 | 操作人、操作类型、时间、描述 |

订单详情 **无附件 Tab**。发票号只在发票模块维护。

### 5.5 GEO 套餐样例（联调用）

生产以官网商品配置为准。当前讲解 / 联调样本：

| 项 | 值 |
| --- | --- |
| 产品 | 蜜度GEO |
| 套餐名称 | 蜜度GEO小程序评估套餐 |
| 单价 | 9.90 元 |
| 总价 | `9.90 × 订购数量` |

## 6. 功能需求二：线上订单发票

### 6.1 页面定位

财务 / 运营处理官网支付订单的开票：查进度、导出开票信息、查看税号账户、上传电子发票附件。  
列表操作列 **仅「详情」**，不提供「作废重开」。

菜单位置：收支管理 / 线上订单发票。  
提示文案：`*线上订单发票来源于官网支付订单。`

### 6.2 列表筛选

| 筛选项 | 控件 | 匹配规则 |
| --- | --- | --- |
| 产品 | 下拉 | 精确 |
| 发票号 | 文本 | 包含；未开票可为空 |
| 开票状态 | 下拉：已开票 / 待开票 / 开票中 / 已作废 | 精确 |
| 公司 | 下拉（开票主体） | 精确；样例：蜜度科技股份有限公司 |
| 发票类型 | 下拉：专票电子票 / 普票电子票 | 精确 |
| 支付方式 | 下拉：微信 / 支付宝 | 精确 |
| 发票抬头 | 文本 | 包含 |
| 开票提交时间 | 日期范围 | 按提交日期 |
| 开票日期 | 日期范围 | 按实际开票时间 |

按钮：查询、重置、导出。

**不提供** 用户名、账号、付款编号、单位属性筛选。

### 6.3 统计面板

随当前筛选结果计算，金额千分位、两位小数：

| 指标 | 计算 |
| --- | --- |
| 待开票金额 | 开票状态=待开票 的开票金额合计 |
| 开票中金额 | 开票状态=开票中 的开票金额合计 |
| 已开票金额 | 开票状态=已开票 的开票金额合计 |
| 已作废金额 | 开票状态=已作废 的开票金额合计 |
| 到账金额 | 当前结果集到账金额合计 |
| 发票总数 | 当前筛选条数 |

### 6.4 列表列

勾选、#、产品、发票号、开票状态、公司、支付方式、支付时间、开票提交时间、单位属性、发票抬头、纳税人识别号、注册地址、注册电话、开户银行、银行账号、发票内容、开票日期、开票金额、发票类型、到账金额、到账日期、未到账金额、操作（详情）。

- 发票号为空显示 `-`。
- 开票状态=已作废时整行文字弱化。
- 不展示用户名、账号、付款编号。

### 6.5 开票详情

标题：`开票详情 【{发票号}】` + 开票状态标签。未开具时标题回退为第一笔订单编号。  
打开详情默认落在「订单信息」。底部：取消（关闭）。

| Tab | 内容 |
| --- | --- |
| 订单信息 | **一行一笔订单**。含用户名、账号、付款编号。不含发票号、发票类型、开票状态、公司、开票金额 |
| 发票信息 | 开票信息 + 发票收件信息 + 到账流水 |
| 附件信息 | 选择类型后上传；支持连续上传；列表可预览 / 下载 / 删除 |
| 操作记录 | 下单、支付、提交开票、开票等 |

开票金额应对齐订单信息表各行「价格」合计（合并开票场景）。

**开票信息字段**：开票状态、开票抬头、发票号、纳税人识别号、税率、开户行 / 银行账号、开票电话 / 开票地址、开票类型、开票内容、备注、开票金额、公司、开票提交时间 / 开票时间、到账金额。

**收件信息字段**：收件人、收件人电话、收件人邮箱、收件人地址。电子票以邮箱送达为主。

### 6.6 附件

上传步骤：选附件类型（必选）→ 选文件 → 备注（选填）→「上传」或「上传并填写下一个」。

附件列表字段：附件ID、类型、附件名、上传人、上传时间、签收时间、备注、操作（预览 / 下载 / 删除）。空态：「暂无附件」。

## 8. 数据与接口建议

### 8.1 订单 Order

```
orderNo                 订单编号 PK
product / packageName / packageDesc
qty / unitPrice / amount
serviceStart / serviceEnd / orderTime
userName / mobile
payMethod / payNo
unitType / invoiceTitle
status                  正常 | 作废
originOrderNo / voidRemark
items[] / invoices[] / flows[] / totalRights[] / logs[]
```

### 8.2 发票 Invoice

一张发票挂 `orders[]`，一行一单。

```
invoiceNo               未开具可空
invoiceStatus           待开票 | 开票中 | 已开票 | 已作废
invoiceEntity           公司（开票主体）
invoiceType             专票电子票 | 普票电子票
invoiceTitle / taxNo / taxRate
bankName / bankAccount
invoicePhone / invoiceAddress
invoiceContent / remark
invoiceAmount / receivedAmount
submitTime / invoiceTime / payTime / receivedDate
receiver / receiverPhone / receiverEmail / receiverAddress
orders[] / files[] / flows[] / logs[]
```

列表「注册地址 / 注册电话」与详情「开票地址 / 开票电话」建议统一为一套购方地址电话。

### 8.3 接口

| 能力 | 说明 |
| --- | --- |
| 订单分页查询 | 入参=筛选字段；列表出参不含用户名/账号列 |
| 订单详情 | 含全部 Tab 子资源 |
| 发票分页查询 | 出参不含用户名、账号、付款编号 |
| 发票统计 | 与列表同一筛选条件 |
| 发票详情 | 含 `orders[]`、开票、收件、流水、附件、日志 |
| 导出开票信息 | 权限控制；范围见待确认 |
| 附件上传 / 删除 / 预览 / 下载 | 类型必填；删除记操作日志；预览下载走登录态 |

### 8.4 权限与安全

- 菜单权限拆分：订单管理-线上订单；收支管理-线上订单发票。
- 手机号列表筛选可用完整号，展示建议脱敏（中间四位 `*`）。
- 附件预览、下载必须鉴权。

## 9. 非功能需求

| 项 | 要求 |
| --- | --- |
| 数据来源 | 官网 / 小程序支付成功后同步；BOSS 只读展示商品与订单主数据 |

| 审计 | 开票提交、开具、附件增删写入操作记录 |
| 兼容 | 本迭代列表不入口的弹窗（开票、退单、作废重开）生产环境不要做对应按钮 |

## 10. 验收标准

**线上订单**

- [ ] 菜单在「订单管理」下，操作仅详情
- [ ] 订单状态只有正常 / 作废
- [ ] 单位属性取值：企业单位 / 非企业单位 / 个人；筛选区无此项
- [ ] 支付方式为微信 / 支付宝
- [ ] 列表无发票号、无用户名列、无账号列
- [ ] 筛选可按用户名、账号查询
- [ ] 详情含用户名、账号、付款编号
- [ ] 详情开票信息表含备注，不含发票号
- [ ] 详情无附件 Tab
- [ ] GEO 套餐描述与单价 9.90 展示正确

**线上订单发票**

- [ ] 菜单在「收支管理」下，操作仅详情，无作废重开
- [ ] 开票状态四态齐全，统计随筛选变化
- [ ] 列表无用户名、账号、付款编号
- [ ] 筛选区无「单位属性」
- [ ] 列表有发票号；未开具显示 `-`
- [ ] 详情默认打开「订单信息」Tab，表格一行一单；支持一票多单
- [ ] 详情订单信息表有用户名、账号、付款编号，无发票号 / 类型 / 状态 / 公司 / 开票金额
- [ ] 详情开票信息有发票号、备注、公司、开票金额、开票类型
- [ ] 附件可选择类型、上传、连续上传、预览 / 下载 / 删除
- [ ] 未到账金额 = max(开票金额 − 到账金额, 0)
- [ ] 已作废行视觉弱化

## 11. 待确认（不阻塞按原型开发）

1. 一笔订单是否允许拆分到多张发票（部分开票）。一张发票对应多笔订单已确认。
2. 「导出」与「导出开票信息」差异：全量筛选结果 vs 勾选行。
3. 列表注册地址/电话 与 详情开票地址/电话 是否强制同一套购方信息。
4. 非企业单位开专票时税号是否必填（需财务确认）。
5. 附件「签收时间」由谁写入（客户确认收到 / 运营标记）。
6. 订单作废后，对应发票是否必须同步「已作废」，以及已开票是否走红冲。

## 12. 讲解路径（便于评审）

建议按同一笔样例「先订单后发票」走一遍：

1. 线上订单列表：看套餐、支付、单位属性、订单状态；强调没有发票号列。
2. 订单详情：用户名 / 账号 / 付款编号只在这里出现；开票信息 Tab 看进度和税号，没有发票号。
3. 切到线上订单发票：同一支付订单进入开票作业；税号账户在宽表上方便财务导出。
4. 开票详情：先看「订单信息」表（一票多单时多行），再看票面、发票号、公司、金额；附件上传电子发票 PDF。
5. 状态：订单只有正常 / 作废；发票四态。已作废行变灰，统计里单独有「已作废金额」。

样例：

| 场景 | 说明 |
| --- | --- |
| 已开普票（一票两单） | 订单 OL202608280017 + OL202608280042 合并开票，金额 13,780.00 |
| 待开专票 | 发票号空 |
| GEO 正常未开票 | `GEO202608050019` |
| GEO 订单作废 | `GEO202607280061`，对应发票已作废 |
